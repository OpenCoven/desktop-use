# X11 cancellation input-state cleanup

The binding goal is issue #21's complete native acceptance, including preserved approval, cancellation and private diagnostics. A real baseline adapter at main `155c30a` left XTest keycode 38 logically held after its `xdotool type` helper was killed and reaped. The controlled reproduction paused the actual helper only after observing keydown, then cancelled the adapter. Cancellation returned `CANCELLED`, helper reaping passed, the key remained down and the fixture received new repeat events. Manual release of only the test-introduced key restored the initial key map and stable fixture counter. Preserve this failure receipt.

PR30 and the native owner explicitly handed this task bounded X11 cancellation code in a fresh-main branch. Mac helper/geometry/validator changes, their source worktree and active Mac sessions remain with the native owner. The owned virtual X11 display is exclusively leased until the recorded expiry, with no network, host mounts or permission expansion. The test harness must always restore its own introduced keys and resume only the exact owned Xvfb server.

## Required behavior

- Reap the in-flight input helper before cleanup; never replay or complete the cancelled text/key action.
- For qualified local X11, release only logical keys attributable to the approved input intent that were not held at action start. Preserve preexisting held keys and the modifier/lock/group state that `--clearmodifiers` temporarily changes.
- Never sweep all 256 keys or release unrelated new keys. X11 state is shared: concurrent physical input with the identical intended key cannot be perfectly attributed from a state snapshot; keep that limit explicit rather than claim per-client ownership.
- Preserve `CANCELLED`, timeout and original failure precedence. Expose only sanitized cleanup state/counts, never text, key identities derived from private input, raw key maps, argv or helper diagnostics.
- Bound state probing and cleanup even when the display is blocked or unavailable. Cleanup must have a short independent budget after the action deadline/cancellation and must not be bypassed merely because cancellation is already set. It must not create a model-accessible approval bypass.
- Keep this a thin platform adapter, with no OpenClaw core, agent orchestration, new global service or automatic system helper installation.
- Preserve normal helper behavior, Unicode/keys/chords where supported, no automatic resend, and existing deterministic contracts. Qualify actual stopped input, no new server events after settlement, helper reaping and preheld/unrelated-state preservation. Separate already-generated queued delivery from new post-cancellation events; do not relabel earlier failures.

## Proposed implementation

Use a small Linux-only X11 state guard around X11 text/key steps. A bounded, owned forked probe loads the existing X11/XTest libraries dynamically, records the initial logical key/modifier state and relevant keyboard mapping, and retains that original X connection throughout the action. A disconnected or blocked connection cannot be replaced by a new server connection during cleanup. This adds no native archive sidecar or link-time platform library dependency. A pure planner limits cleanup to the approved request's keycodes and helper-generated modifiers; unmapped Unicode scratch-key handling must follow the qualified helper's actual algorithm or remain visibly unverified.

After an abnormal result and helper reaping, the same private child inspects state through its original connection, releases only attributable newly held keys, restores helper-cleared preexisting modifiers/lock/group state and reports sanitized verification within an independent cleanup budget. It uses no shell or raw input in process arguments. The child is bounded and reaped on every path; EOF requests cleanup after unexpected parent death, with a watchdog for blocked server operations. No hidden production command or environment variable grants new input authority; interactive dispatch retains the existing `--confirm` check before guard startup.

The same X11 shared-state limit already affects synthesized key-up semantics; the guard must not broaden it to unrelated keys. Unknown mappings/server identities must be reported honestly. A design review must settle whether inability to prepare a guard should reject input before effects or preserve existing helper success with cancellation cleanup explicitly unverified; do not silently turn every existing supported X11 action into unsupported or falsify deterministic helper evidence.

Alternatives considered: a global `keyup` sweep is rejected because it releases unrelated user state; waiting for all requested typing to finish after Stop is rejected because it continues cancelled input; changing XTEST to XSendEvent is rejected because application behavior and delivery support differ; patching/bundling a separate helper or replacing the input backend is a larger compatibility and distribution change than the demonstrated adapter cleanup defect.

## Builder-check decisions

The fresh builder check identified five material implementation questions. All are implementation choices within the authorized native fix; no new user approval gate is required.

1. Preserve the existing helper route in unavailable or unqualified environments, with sanitized `unverified` cleanup after failure. Verified native cancellation acceptance requires a prepared guard. This preserves deterministic fake-helper contracts without presenting them as native state evidence.

2. Keep one private child and the original X connection for the action lifetime. It receives private parent instructions, performs bounded cleanup after the helper is reaped, and exits. EOF after unexpected parent death requests cleanup; a real-time watchdog bounds blocked display operations. There is no reconnect to a replacement server or persistent service.

3. Qualify the registered system helper and fixed libxdo 3.20160805.1 ABI. Use that library's actual ordered character map, aliases and generated modifier selection; do not guess with XKeysymToKeycode or silently correct its scratch-selection algorithm. Unknown/ambiguous plans remain unverified.

4. For a prepared guard, split typing into the same Unicode scalar units the qualified helper processes internally. Arm only the imminent character/key/chord, so a future character elsewhere in the request cannot authorize release of an unrelated newly held key. Keep public logical step summaries bounded; never emit one JSON result per character. Preserve the original action deadline and no resend. Measure actual throughput on the existing native case. Unqualified execution keeps its original route.

5. Compensation is limited to the current input's newly held keys/generated modifiers and preheld state the actual helper could clear/touch. Preserve unrelated keys, locks, groups, pointer location and mapping rows. Restore preheld buttons only if --clearmodifiers could release them and the pointer has not moved. Restore only the helper-cleared Caps Lock bit, and only the temporary group and scratch mapping whose current shape matches a qualified helper operation; explicit lock-key input is an approved partial effect, not an automatic rollback. Concurrent external changes to the same intended state remain explicitly indistinguishable and cannot be claimed as per-client ownership.

Native cleanup metadata must survive SDK/MCP cancellation projection and typed-input redaction through a strict enum/count allowlist. Missing or invalid native cleanup evidence becomes visibly unverified. Shared process failure precedence and raw-diagnostic suppression remain intact. Additional process-runner/core sanitizer paths require their explicit owner handoff before edits.

## Native refinement

The first per-scalar candidate passed the held-key interruption but emitted extra Shift restoration presses during normal typing. Preserve one modifier-clear/restore transaction per original logical step, while retaining imminent-scalar input intent. The child refreshes its ordered libxdo map on the same X connection before each logical step. It removes helper --clearmodifiers only on the qualified route, restores state at the logical boundary, and reports any inability to verify visibly without replaying input. Cleanup frames have a distinct marker so a pending activation acknowledgement cannot corrupt cancellation evidence.

The qualified helper may reset a used scratch row to all zeros even when its original first column was zero and later columns were populated. Restore that exact saved row only after known scratch use and a matching helper-written or helper-zeroed shape; unknown mapping changes remain unverified. Mapping comparisons ignore trailing zero padding, which is not a different keyboard binding.

Mapped Unicode effects require their own controlled layout proof. The default virtual US layout showed unstable empty GTK events on both original and candidate transient scratch bindings; preserve those failures and do not claim default Unicode effect acceptance from a cleanup receipt. A separately authorized two-row mapped-layout test proves actual é/emoji fixture text and complete mapping restoration.

## Persistent external helper refinement

A later native throughput regression rejected the per-scalar process implementation: a 600-character request completed in43ms on the baseline but took4690ms on the candidate; the same valid1000ms deadline timed out after134 characters. Pipe readiness polling alone remained insufficient. Keep the qualified external helper and use its existing fixed-version script mode in bounded 4096-scalar chunks. The helper receives deduplicated literal scalar argv operands. Its stdin contains only generated `type --delay 0 --args 1 $N version` frames; positional expansion occurs after its tokenizer, and raw input never enters that parser or a shell. The guard still arms and completes one imminent scalar at a time, and modifiers are cleared/restored once per original logical step across all chunks.

An initial fixed version command verifies readiness and initializes the helper even for empty text. Each scalar requires its same-line exact version acknowledgement, with stderr checked before stdout and again before accepting acknowledgement. Any helper diagnostic is a fixed backend failure on this qualified route; debug mode is removed from that helper environment and raw bytes remain withheld. This intentionally fails visibly on helper warnings instead of accepting an uncertain effect. No next-line acknowledgement may mask a failed command. Success closes stdin only after the final complete acknowledgement, drains both streams and requires successful helper exit. Failure kills the owned group before closing stdin, because the helper can execute an unterminated final line at EOF, then reaps before compensation. Exit is observed without reaping while killing owned descendants, preventing a reused PID/group from becoming a cleanup target.

Chunks keep protocol output below the unchanged 1 MiB per-helper combined output cap. Failed E2BIG exec preparation may reduce a chunk before any scalar is sent, under the original deadline; a sent frame is never retried. Chunk preparation never changes model authority or grants access to a new executable. The revised 600-character 1000 ms native case passes at51ms against26ms baseline. No deadline, test assertion or output cap was extended. Literal control/quote/dollar/hash/hyphen, mapped Unicode and multi-chunk operand tests must accompany the final source review.

## Reviewed lifecycle and proof corrections

The fresh review required actor quiescence before parent-EOF compensation. Actors register an identity-safe pidfd through a private pre-exec handshake before effects. The guardian retains a duplicate of text stdin until actor exit, preventing a partially written frame from executing at EOF when the original parent dies. Normal shutdown explicitly releases that hold only after complete acknowledgements. Actor death is observed before compensation; normal parent supervision reaps, while a test or OS subreaper collects already dead actors after a parent crash. A parent-death signal bounds the guardian even when an Xlib probe is blocked. No arbitrary PID supplied by a model is accepted.

Both keyboard actions share cleanup redaction for direct adapter JSON, injected results, nested steps and process failures. Regressions must reject invalid enums/counts/raw state on keypress exactly as on type-text. Timing proof captures the actual API promise settlement and a pre-input event cursor, then checks the complete observed interval; equal millisecond boundaries remain ambiguous. Harness TERM/INT handling, owned-descendant containment and restoration must run before any success or interruption handoff. Artifact binding occurs after every build finishes, serially, before native qualification; later builds invalidate that binding until refreshed.
