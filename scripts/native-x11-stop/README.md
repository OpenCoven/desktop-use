# X11 input cancellation qualification

These opt-in scripts operate only on an exclusively leased disposable Xvfb display with the controlled GTK fixture. They are real XTest and packed-client evidence for that virtual session; they do not establish physical desktop, macOS, Wayland, release or human acceptance. They install no helpers and change no host settings. Supply exact artifact hashes, server and fixture identities, and the current lease expiry. Do not run them against a shared display.

The native guard qualifies the system `/usr/bin/xdotool` linked to libxdo version `3.20160805.1`, with existing libX11 and libXtst. Other environments keep the original helper route and report unavailable cleanup as unverified after failure. The guard uses one retained X connection and a private supervised child, clears and restores modifiers once per original logical step, and arms compensation only for the current scalar or chord. Cleanup runs after helper reaping. Its fixed result fields contain counts and verification state, without input text or raw keyboard mappings.

`qualify.py` compares baseline and candidate modifier transitions, interrupts actual held keys on cancellation, timeout and helper failure, preserves preheld and unrelated keys, and verifies held-button and Caps Lock restoration. A bracketed server-clock calibration distinguishes queued events delivered after return from events generated afterward; ambiguous events fail the regression. Preheld keys are deliberately preserved, so their existing repeats are not described as new cancelled input. Recovery releases only test-introduced keys and restores test-introduced button, pointer and lock changes.

`faults.py` tests blocked readiness, blocked cleanup and parent-pipe EOF. A blocked server must produce bounded unverified cleanup, with the owned guard reaped. An independent identity-bound resumer protects the deliberate server pauses. Parent-crash cases require the surviving guard to stop the input helper before compensation, including while the display is blocked. The test-local subreaper only collects the already terminated orphan; it does not kill that helper to satisfy the gate. A separate blocked-probe case verifies that parent death also bounds a guardian stuck before readiness. Unavailable server state remains an explicit recovery requirement.

`consumer-driver.py` launches `consumer.mjs` from a separate production-only packed installation containing the pinned official MCP client. It observes and pauses the actual helper with its key down, then exercises SDK Stop, Abort and timeout plus Stop and timeout on both actual MCP wire revisions. The broker uses the real reference terminal host with scripted trusted decisions, which are distinct from human approval evidence. Results must preserve cancellation/timeout, partial-input facts and verified cleanup, reap the helper, leave no held key or late fixture events, and exclude the harmless repeated input from audit/results. Supply the existing test PTY driver explicitly; it is not an installed runtime dependency.

`mapped-unicode.py` additionally requires an explicit two-row mapping grant. It saves the full keyboard map and modifier map, selects exactly two unused nonmodifier rows, compares actual fixture text from the baseline and candidate, then restores and verifies the complete original mapping through the same connection. Its signal handlers and subprocess timeouts enter the same unconditional recovery. A hard kill or host failure still requires the lease holder to inspect and recover the owned session. The default helper's transient unmapped Unicode bindings can disappear before GTK translates the event; those runs remain an explicit gap and do not inherit a mapped-layout pass.

Every script provides `--help`. Keep receipt destinations outside the source checkout. Run native scripts sequentially, retain first failures, and inspect their recovery fields before returning the display lease. After a mapping-test interruption, verify the recorded original rows and modifier-map exclusion before resuming any other work. Never sweep all keys or restore another session's mappings.

Cleanup verification is limited to qualified intended state and helper-cleared preheld state. X11 shares logical state across clients; a concurrent physical press of the identical intended key cannot be attributed perfectly. Unrelated changes remain untouched. A `verified` cleanup receipt does not prove Unicode text delivery, complete rollback of partial effects, or universal desktop safety.

Qualified text execution uses the existing external helper's script mode in bounded 4096-scalar chunks. Scalars are deduplicated literal argv operands; only generated positional references enter the helper parser. It receives one frame at a time after the guard arms that scalar. Exact same-line version acknowledgements establish completion. The unchanged 1 MiB combined output cap applies separately to each real helper, and preparation can shrink a chunk after an E2BIG exec failure before sending any scalar. Sent frames are never replayed. Cancellation kills before closing stdin so a partial frame cannot execute at EOF. Successful shutdown requires drained streams and exit zero. Helper diagnostics fail visibly with fixed messages on this qualified route, and helper DEBUG mode is suppressed; diagnostics are never returned or persisted.

The native regression includes600 characters under the original1000ms deadline, with actual fixture counts, plus literal tab/newline/quotes/backslash/dollar/hash/hyphen operands. Pure owned-IPC tests cover multi-chunk completeness, literal operand preservation, missing acknowledgements with private stderr, empty input, partial-frame termination, extra stdout and nonzero exit. A faster deadline result is not native graphical proof without the fixture's observed changes.

The surviving guard registers helper identity through a pre-exec handshake and a Linux pidfd. Before private text frames are sent, it retains an identity-checked duplicate of the helper stdin writer. Parent death therefore cannot turn a partial frame into EOF execution: the guard kills and observes actor exit before releasing the writer and restoring input. Normal shutdown releases the hold only after the final exact acknowledgement. A parent-death signal caps a blocked guardian operation at100ms without extending a shorter watchdog. Qualified cleanup requires pidfd support and same-owner `/proc` descriptor access; unavailable environments retain the original helper route with unverified cleanup.

All scripts register recoverable TERM/INT handling before mutation and contain only their own descendants through a Linux subreaper. The platform guard gets its bounded cleanup grace before test-process escalation; actors are stopped and reaped before restoring input or keyboard mappings. `qualify.py --interrupt-after-held-key` and `mapped-unicode.py --interrupt-after-layout` exercise actual leased termination paths. Hard host failure remains an operator recovery case; keep the display lease until recorded state recovery is verified.

Event cursors are saved before input and client clocks are sampled immediately at SDK/MCP promise settlement. Every subsequently observed event is classified across the complete interval, including events delivered before a later observer snapshot. Equality within the clock's millisecond boundary is ambiguous and fails qualification. Queued pre-return events remain separately counted.

Cancellation coordinators require the actual helper to remain paused with its intended key down across a 25 ms observation interval before triggering cancellation. If a paired key-up was already queued, they resume that identity and seek another held boundary within the original test deadline. This strengthens the fault-injection boundary without changing action deadlines or excluding events from timing verification. Retain failed or ambiguous timing receipts alongside any later conclusive run.

`pointer-driver.py` checks an actual CLI double-click cancellation against the same exclusive fixture and exact native identity. Its required `--trace-owned-helper` observer addresses the qualified helper's brief down/up interval by tracing only the exact owned click helper, then reaching an actual SIGSTOP signal-delivery stop and detaching before cancellation. It requires one thread, unchanged process birth and executable, zero tracer and a real stopped state with button 1 down across 25 ms. This is controlled scheduling fault injection: helper bytes, arguments and production deadlines stay unchanged, but tracing changes timing and can interrupt syscalls. No extra capabilities, seccomp changes or preload hooks are used. Refused tracing, missed boundaries and unresolved cleanup remain unqualified. A pointer pass requires helper reaping, the button released before manual recovery, CANCELLED and verified cleanup with exactly one released button; it does not establish application repaint or physical desktop acceptance.

With `--consumer`, the pointer driver runs `pointer-consumer.mjs` from a separate packed production installation and routes cancellation through SDK Stop/Abort/timeout or Stop/timeout on both actual MCP wire revisions. A clock-only Python/Node handshake brackets Linux monotonic time before input. The coordinator records conservative observation-end nanoseconds for actual button release and helper disappearance while the consumer remains pending; both must strictly precede the consumer's first fulfillment callback timestamp. Missing, equal or late observations remain unqualified. The reference MCP approver is driven through its real PTY, while the SDK uses an explicitly scripted trusted provider. Neither is human approval acceptance.

`button-state-driver.py` prepares only test-owned held buttons at the controlled target, then verifies cancellation preserves the preheld intended button or an unrelated button. Cancellation requires the same owned trace observer. Its untraced completed-click case checks restoration at the unchanged pointer: one restoration for the touched preheld left button and none for the unrelated right button. It compares the full button mask and actual keymap before manual recovery, then requires restoration of initial button/key state. A pre-existing intended-button boundary is labelled as such rather than described as a newly generated press. These CLI checks make no SDK/MCP fulfillment-order claim.

`held-lock-startup.py <absolute-adapter> <sha256> <new-receipt>` is a separate component regression that owns a fresh Xvfb server inside a newly created disposable container, with `NATIVE_OWNED_DISPOSABLE_DISPLAY=yes`. It refuses an existing display socket or lock. Actual held Num Lock and Scroll Lock states must retain the original successful keyboard fallback while pointer cleanup remains available. It restores the exact initial keys and locked modifiers/group and reaps its server in unconditional recovery. This does not prove a visible graphical effect or physical acceptance.

Same-point qualification reproduced the original helper's `mousemove --sync` departure wait on both the baseline and initial pointer candidate: an ordinary click already at its target timed out with no clicks. The corrected click chain keeps movement and click on one ordered helper connection and removes that wait, preserving literal coordinates, button/repeat operands and action deadlines. Qualification drivers bind the exact new argument form; earlier receipts stay associated with their earlier source and native hashes. Re-run the complete native matrix after changing that form.

Run the observer's process-only tests inside the owned Linux namespace with `PYTHONDONTWRITEBYTECODE=1 python3 -W error -m unittest discover -s scripts/native-x11-stop -p 'test_owned_trace_stop.py'`. They exercise real child and grandchild stops, unrelated signal delivery, interrupted/timeout cleanup, exact native-parent wait status, and rejection of wrong identities, executables and multiple threads. A boundary fault test substitutes a real replacement process at numeric ATTACH while retaining the original pidfd; the observer must unwind its attachment with no injected signal and leave both processes alive. These tests do not require a display and do not constitute native input acceptance.
