# Native pixels through the packed OpenClaw plugin

This opt-in driver is separate from the release matrix. It uses one explicitly selected official host, one installed packed plugin, a real native adapter and an exclusively handed disposable fixture. It never installs helpers, changes privacy grants, launches the fixture or accesses a live model service. Default preflight only reads selected files.

Prepare a descriptor outside the repository with `schemaVersion:1`, `sourceCommit`, `sourceTree`, `packageVersion`, `pluginRoot`, `packageArchive`, `packageSha256`, `adapter`, `adapterSha256`, `host`, `hostVersion`, `platform`, `fixtureState`, `fixturePid` and `fixtureWindowId`. Paths must be absolute. Preflight derives the complete unique file inventory directly from the hashed package archive and compares every installed file, rejecting extra files outside the separate `node_modules` dependency directory. Supplied inventories cannot authorize omitted or changed executable modules. Source association is an owner handoff; copied byte identities are checked independently. Any embedded package identity must agree. This does not establish public publication or cryptographic provenance.

For macOS include `fixtureBundleId`, `helperExecutable`, `helperSha256`, `helperVersion` and `helperSourceCommit`. An explicit `captureEngine` records its actual setting, for example `cg`; it cannot turn the helper's failed `auto` case into a pass. For Linux set `ownedDisposableDisplay:true` and execute inside the owner's dedicated graphical environment; this is not permission to use the user's desktop.

Linux also requires the GTK bridge from the native-client acceptance harness and `fixtureBridge:{script,sha256}` in the descriptor, naming its exact absolute script path and selected SHA-256. Set `fixtureState` to that bridge's fresh flat receipt. Each Linux fixture read verifies live bridge and GTK process/start identities, the exact selected bridge source and invocation/output path, and an acquisition timestamp no older than one second before and after asynchronous validation. A dead bridge, changed source or expired receipt fails before it can serve as an input or no-effect oracle.

Linux offline startup may explicitly select `hostRuntimeStage:{baseDir,inventory,inventorySha256,manifestSha256,lockSha256}` in the trusted descriptor. Both paths are absolute; the inventory must live outside the stage base. This optional lane currently pins the unchanged official 2026.4.26 resolver by SHA-256. Its read-only helper derives the external package key from the actual host path and scans all declared provider dependencies. The base must contain only that package key. The separately hashed inventory has `schemaVersion:1`, `hostVersion`, `hostPackageRoot`, `packageKey`, `helperSha256` and complete `files` entries relative to the install root. Each regular file records `path`, `bytes`, `sha256` and boolean `executable`; each internal file link records `path` and `symlink`. Duplicate, omitted, extra, changed or escaping entries fail. Every installed dependency version must match the retained npm v3 lock, every non-optional locked dependency must exist, and the private manifest must exactly match the host scan. Missing optional packages are counted separately. The selected stage must satisfy the host's complete dependency scan without installing anything.

Preflight and the check immediately before gateway spawn verify that complete selection. Only the verified base is forwarded as `OPENCLAW_PLUGIN_STAGE_DIR`; ambient stage selections and npm caches are ignored. Preparing or installing this stage is a separate explicitly authorized task; this driver never downloads, installs, repairs or patches host files. Stage preparation must preserve all official host archive bytes and retain its manifest, lock, resolved versions and file inventory. Default preflight remains read-only and an omitted stage retains ordinary host behavior. Stage verification is preparation evidence, not successful gateway startup or native/provider acceptance.

Native execution additionally requires `hostArchive`, `hostOrigin:"unchanged-official-package"` and a fresh `fixtureLease` object with `acknowledgement:"native-openclaw-fixture-exclusive"`, `ownerThread`, `expiresAt` less than one hour ahead, and the exact `fixturePid`, `fixtureWindowId`, `adapterSha256`, `packageSha256` and `sourceCommit`. The host archive must match the pinned official registry integrity; every installed host file must match that archive. Obtain the lease from the actual fixture owner before running; do not fabricate an acknowledgement. The owner must hold its own native activity during the lease and explicitly authorize the fixture-only scripted input. Lease, fixture identity, counters and geometry are checked again immediately before allowing input. Expiry cancels the workflow.

The fixture state must expose `ready`, `pid`, `windowNumber`, `clicks`, `desktopRect` and `targetRect` with the native client fixture's semantics. On macOS it must also expose the independent AppKit `windowFrameRect` (including window decoration) and `backingScale`. Both must remain unchanged through the pre-capture and pre-input lease checks. Target colors are the fixture's known sRGB red `(224,48,64)` before the first click and green `(32,192,96)` afterward. Pixel decoding converts to sRGB and declares a 16-level channel tolerance.

For macOS, one mapping must cover the entire decoded image, and all four mapped desktop edges must match the independent window frame within one point. Pixel scale must be uniform and match 1x or the fixture's native backing scale within 0.01. A larger screen or cropped window containing the correctly positioned target is rejected. The sanitized receipt reports `independentWindowExtentVerified`, frame, scale and tolerances separately from the provider's unchanged `actualScope`. An explicitly unavailable provider scope remains unavailable; contradictory available scope is rejected. This independent proof establishes capture footprint and target position, without proving semantic ownership of every pixel or general full-frame distortion. Linux retains its verified frontmost provider-scope requirement.

```sh
node scripts/native-openclaw-acceptance/run.mjs /owned/descriptor.json --preflight
NATIVE_OPENCLAW_HOST=/owned/official-openclaw node --test scripts/native-openclaw-acceptance/*.test.mjs
# Only after the explicit final-byte and fixture lease:
node scripts/native-openclaw-acceptance/run.mjs /owned/descriptor.json --run-owned-fixture /owned/fresh-private-run
```

The selected host must supply Sharp 0.34.5 and ws; archive inspection uses Python 3.11 or later without extracting or executing archive contents. The fixture must start at zero clicks, so the permitted click creates a directly checked red-to-green transition. The driver starts an isolated loopback model server and gateway, limits the agent to `computer_use`, captures only the fixture, verifies the exact current capture call, timestamp, unreused observation ID, provider-wire image identity and all target edges against independent geometry, and derives a coordinate click from those received pixels. A real approval RPC permits one click; another case supplies forged confirmation but denies the real approval. Fixture counters and fresh after-capture pixels must agree. Decisions are scripted trusted-operator decisions, not human acceptance.

The fresh runtime root is mandatory. Raw provider payloads are never written by the driver. SIGINT, SIGTERM and lease expiry enter cleanup; pending setup acquisitions settle before cleanup inspects or closes their resources, and cancellation prevents subsequent spawning. An operating-system filesystem call can delay that settlement. The driver samples gateway descendant/start identities every 100 ms while the leader is alive, aborts owned runs, terminates positively identified process groups and checks tracked processes and groups are gone. Sampling cannot establish ownership of an unobserved detached descendant after its leader exits. An already exited leader therefore produces incomplete ownership status even when retained tracked processes were removed; it cannot report successful cleanup from an empty snapshot. The driver checks durable audit and diagnostic files, then removes its own private gateway state, config and logs, including the official host's last-good, backup, clobbered and rejected config copies. Backup symlinks are removed without following them outside the fresh root. Only sanitized metadata receipts remain; cleanup failure preserves incomplete status. Native, virtual display, physical display, source, official-host compatibility and public release gates stay separate.

Tool-call identities use short alphanumeric case digests so the pinned official host's strict replay leaves them unchanged. Capture-result and approval-event identity checks remain exact; replay normalization cannot authorize a mismatched result. The helper tests run the actual official replay sanitizer, including its 40-character limit. Failure receipts retain fixed phase/class/code values and selected verifier module/line numbers; arbitrary messages, assertion values, stack paths and payloads are withheld. `providerHttpRequests` counts requests received by the local endpoint independently of the validated observation flag. Cleanup also removes the pinned host's exact PID/UUID temporary config filename pattern, which can survive interrupted writes; unrelated similarly named files remain intact.

Native attempts on the prior driver reached the real Linux virtual-X11 backend and the unchanged official gateway, but failed capture-call identity proof before approval or input because host replay removed punctuation from generated IDs. Separate earlier attempts failed fixture setup or offline gateway startup. These failures and successful tracked-process cleanup do not establish native acceptance. Fresh execution on the reviewed repaired driver and the final fixture bytes remains required, as do macOS and physical-display gates.
