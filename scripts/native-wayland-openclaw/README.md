# Owned Wayland pixels through OpenClaw

This opt-in qualification driver uses the frozen matching package/native pair, an unchanged official OpenClaw 2026.4.26 installation, a software headless Sway 1.7 output, and the source-bound GTK fixture. It owns no product runtime and installs nothing. Source preparation and unit results do not establish actual provider or native acceptance.

The provider-specific operator derives from the explicitly handed PR40 source `872e5d8`; its source binding and original ownership remain separate. The six foundation files in `foundation-binding.json` retain their exact `d6ef3e6` bytes. The shared OpenClaw helpers retain the reviewed `235bb06` dependency. Any source change requires new prepared hashes and fresh qualification; historical receipts are unchanged.

Prepare a private descriptor outside the repository with source/tree and harness identities, a complete installed package inventory matching the selected archive, canonical executable/helper paths and hashes, an exact `harnessSources` map for the operator's runtime whitelist, a disposable consumer root, and an `ownerThread`. The `openclaw` object selects the official host, version, archive/hash, `hostOrigin:"unchanged-official-package"` and optional fully verified offline runtime stage. Default operator preflight checks these selected metadata/artifact identities without executing tools or creating a fixture/output. Official host archive integrity and its full installed/staged file inventory are separately checked by the shared component preflight before provider execution.

```sh
python3 -I -B scripts/native-wayland-openclaw/provider-operator.py --prepared /owned/prepared.json
# Only after a source-bound exclusive runtime/fixture lease:
NATIVE_OWNED_DISPOSABLE_DISPLAY=yes python3 -I -B scripts/native-wayland-openclaw/provider-operator.py --prepared /owned/prepared.json --execute --owned-disposable-display --output-root /owned/fresh-run --scale 1 --lease-expires-at TIME_WITH_ZONE
```

Execution requires nonroot Linux, no `/dev/input` or `/dev/uinput`, a fresh canonical output, exact prepared sources and helpers, and a timezone-qualified epoch/monotonic lease of at most twenty minutes. The operator reserves 165 seconds for cleanup, including thirty seconds of graceful shutdown per direct actor, three seconds of kill/reap and a separate subreaper drain. An outer namespace lease must leave enough additional time for that cleanup and stopped export. Expiry is not proof of a terminal process; runtime custody returns only after actual terminal/reap/namespace-state inspection.

The operator creates its own private Sway runtime and fixture, checks the focused window, and prepares a static PID/window file only for shared package/host preflight. That file alone cannot authorize capture or input. Every actual observation additionally reads the bounded regular owned fixture file between fixed-worker live compositor/PID/birth/source/socket-peer checks, requires the entry focus and matching geometry, and returns only validated layout, counts and text hashes. The fixture writes only on changes, so its file timestamp is not used as a GUI completion fence.

The runner starts one isolated local deterministic image-capable provider and an unchanged official gateway. It marks the operator-verified helper PATH as already bootstrapped, using the official host flag, so the gateway cannot prepend a different system grim ahead of the pinned JPEG build. It emits a screen PNG capture, verifies the supported typed user image block, decoded bytes, opaque target/landmark regions and independent logical mapping, obtains a real trusted approval RPC, and sends one bounded ASCII marker to the already focused fixture entry. A subsequent JPEG case supplies forged model confirmation but actually denies approval. A JPEG capture is proved before any input, followed by all four before/after cases; five image proofs and exact control/hash transitions are required. Fixed failure-stage, bounded current-turn counts and allowlisted capture outcomes aid diagnosis without retaining payloads. The verified expected fixture observation persists across all cases; a between-case change cannot become a new accepted baseline. Each provider step is consumed before its response is emitted; a repeated or out-of-order request fails rather than resending an action.

Positive effect completion uses the exact observed text hash, character and key counts. Capture-only and denied cases compare every supported control for a labeled 250 ms observation interval and after-capture; that bounded observation does not establish general UI quiescence or repair the separately failed raw-API Stop experiment. Keyboard input does not qualify unavailable pointer input. The runner checks audit and diagnostics for the planned private marker and encoded images, removes its known private gateway state/config/logs, and reaps tracked gateway groups. The outer operator terminates/reaps its actors and adopted descendants, independently removes nested provider private state even after a crash or forced kill, and removes outer fixture files including the atomic-write temporary file, descriptors, logs, home and runtime. It preserves the sanitized provider receipt and never follows cleanup symlinks outside the owned paths. Metadata receipts and the controlled independent image remain.

Run `NATIVE_OPENCLAW_HOST=/owned/official-openclaw node --test scripts/native-wayland-openclaw/*.test.mjs`, `python3 -I -B scripts/native-wayland-openclaw/operator.test.py`, `pnpm run check` and `pnpm run test:packed` on the final bytes. Actual native/provider runs at each scale, physical/human acceptance, macOS acceptance and the strict delayed GTK gate remain separate requirements.

For a separately approved capture-only lease, add `--observe-only` to the operator execution command. The operator binds that selection into both the descriptor and fixture lease and calls the runner with `--observe-owned-fixture`; a mismatch rejects before provider execution. This subworkflow restricts the plugin to `observation-only` with `screenshot` eligible and the mandatory `stop` safety action retained, emits two capture-only PNG/JPEG cases, rejects any input step, requires zero approval events and an audit containing exactly two successful screenshots, and independently checks unchanged fixture controls. The default full workflow still requires all five original cases and the approved input, denial, privacy and cleanup gates.

Observation receipts explicitly report `observationOnly:true`, `readOnlyObservationVerified:true` only on success, and `fullQualificationPassed:false`, `effectVerified:false`, `approvedInputTested:false`, `inputPrivacyTested:false`. They provide capture and mapping evidence only. A clean observation diagnostic does not test privacy of typed input and cannot repair or upgrade the recorded full-workflow privacy failure. The outer operator rejects observation receipts in full mode, takes the independent final controlled image only after the requested subworkflow passes, and clears its success claims if cleanup fails. Observation mode also requires a fresh source-bound exclusive lease; no previous input lease is reused.
